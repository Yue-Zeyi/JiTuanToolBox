## 一、2.0 与文件兼容策略

项目调用的仍是官方 `security.mediaCheckAsync` 接口，但参数固定为：

- `version: 2`
- `mediaType: 2`（图片）
- 当前云函数上下文中的 OpenID

后台出现“1.0 已停止更新”时，不需要更换接口名称；关键是请求参数必须带 `version: 2`。部署本项目的新云函数后，在云函数日志中确认请求参数为上述值，并确认没有旧云函数或旧版本代码继续发起 `version: 1` 请求。

官方单个检测文件上限为 10MB，直接支持 JPG、JPEG、PNG、BMP、GIF。工具本身仍允许单张 20MB，并支持 WEBP、JFIF、JPE：超过官方限制或真实格式不受支持时，小程序会在本地生成不超过 10MB 的 JPEG 检测副本。检测副本不替换原图，工具仍处理用户选择的原文件。

## 四、配置回调

1. 自行生成 32 位不可猜测的随机英文字母和数字作为 Token（微信允许 3 至 32 字符），不要写入小程序前端或代码仓库。
2. 在 `media-security-callback` 云函数环境变量中添加：

   `WECHAT_CALLBACK_TOKEN=你的Token`

3. 为该函数开启 HTTP 访问服务，复制 HTTPS 地址。
4. 确保网关把 `httpMethod`、`queryStringParameters`、`body`、`isBase64Encoded` 原样传给云函数。
5. 登录微信公众平台，在“开发管理 / 开发设置 / 消息推送”中填写：

   - URL：回调函数的 HTTPS 地址
   - Token：与环境变量完全相同
   - 消息加密方式：明文模式
   - 数据格式：JSON

保存时微信会发送 GET 校验请求。函数校验 `signature`、`timestamp`、`nonce` 后原样返回 `echostr`。

回调首先验证签名和 `appid=wxc4716148be4731f9`。只在 `MsgType=event`、`Event=wxa_media_check`、`FromUserName` 非空、`version=2`、`errcode=0` 全部成立时接受 `suggest`。`FromUserName` 是平台推送服务用户名，不是上传用户的 OpenID，不能与任务 OpenID 比较。任务通过 `trace_id` 关联，客户端查询仍校验上传用户的 OpenID。

## 六、链路说明

1. 客户端准备好符合官方限制的检测文件。
2. 客户端调用 `reserve`；云函数生成随机预约号，将本环境存储桶中的唯一文件路径、文件 ID 与当前 OpenID 绑定后返回路径，不创建占位文件。
3. 客户端把检测文件上传到该随机路径，再以 `reservationId + fileID` 调用 `submit`。文件创建者是上传用户，因此兼容私有存储规则。
4. 云函数校验预约归属、状态、路径和文件 ID，标记为 `submitting` 后调用 `mediaCheckAsync` 2.0。
5. 云函数用 `trace_id` 建立任务。若官方回调先到，回调函数先写入待处理集合，任务建立后立即吸收该结果。
6. 客户端轮询当前用户的任务；只有 `pass` 放行。整段检测在客户端有 120 秒硬截止时间。
7. 回调或定时任务删除临时文件。删除接口返回单文件失败状态时，不会伪造已清理时间，后续定时任务会继续重试。

多图最多同时检测三张，检测副本准备在本批次内串行执行。支持时使用独立离屏画布；旧基础库回退到页面画布并按画布实例隔离导出操作，防止晚返回的导出串图。若旧版页面画布的原生导出永久不返回，为保证检测文件与原图对应，不会强制复用该画布；退出并重新进入工具页面后重试。

## 七、真机验收

1. 在开发者工具中重新部署两个云函数，然后点击“编译”；无需重启开发者工具。
2. 打开任意图片工具，选择一张合规图片。
3. `media_security_jobs` 应先出现 `reserved/submitting` 预约，随后出现 `_id=trace_id` 的 `checking` 任务。
4. 收到回调后，任务应变为 `pass`；违规或疑似违规任务应变为 `rejected`。
5. 确认 `security-temp/` 对应文件被删除，任务的 `cleanedAt` 有值。
6. 真机验证合规图片可进入工具；违规图片只提示“所发布内容含违规信息”；断网、云函数错误、回调错误和超时都不能把图片加入工具。
7. 分别验证 JPG、PNG、BMP，以及 WEBP、JFIF/JPE、10MB 至 20MB 图片；后三类应使用本地 JPEG 检测副本。

## 八、常见问题

- 仍提示 1.0 停更：重新部署 `media-security`，检查日志中的 `version`，并排查是否还有其他旧代码调用该接口。
- `wx.cloud.callFunction media-security` 返回 500：先重新部署 `media-security`，并在云函数日志中搜索 `[media-security]`。重点看是否为 `wx-server-sdk` 未云端安装、`media_security_jobs`/`media_security_callbacks` 集合不存在、`security.mediaCheckAsync` 权限未生效、云环境 ID 不一致或仍运行旧版本代码。
- 一直检测超时：检查消息推送 URL、Token、JSON/明文配置以及回调函数日志。
- 提示服务未配置：检查 `wx.cloud.init`、`cloudEnvId` 和两个云函数是否属于同一 AppID/环境。
- 真机上传失败：检查云存储写入权限、客户端环境 ID，以及预约返回路径是否位于 `security-temp/`。
- 回调有记录但任务未更新：检查 `media_security_callbacks` 集合是否存在且云函数可读写。

不要在小程序代码、云函数代码或仓库中保存 AppSecret、`access_token` 或回调 Token，也不要为开发、审核或真机环境添加跳过检测的条件。
