# 极团工具箱 · 全部工具方案

日期：2026-09-08。状态：第三版设计评审稿，尚未接入小程序。业务分类已确定为：图像、文本、文档、查询、计算。

## 1. 结论

推荐独立的“全部工具”二级页面，采用顶部分类 Tab，不使用左侧分类栏。首页继续保留常用工具和文字工具快捷入口。以后新增的工具默认收录到全部工具，不再持续堆叠首页。

第一版高估了分类数量，侧栏占用了手机约五分之一的内容宽度。按已确定的五类业务分类考虑，顶部 Tab 更合适：工具展示更宽，描述更容易阅读，也不会因为分类少而出现大块空侧栏。

| 方案 | 优点 | 局限 | 建议 |
| --- | --- | --- | --- |
| 弹窗 / 半屏面板 | 少量入口打开快，首页上下文仍可见 | 键盘挤压内容；多分类、长列表和返回状态处理不自然 | 不作为完整工具目录 |
| 独立页面 | 搜索、分类、长列表更清晰；可直接分享；方便持续扩充 | 从首页多一次页面跳转 | 本次采用 |
| 新增“工具”底部 Tab | 高频访问更直接 | 改变现有首页 / 记录 / 我的导航，当前与首页重叠较大 | 暂不增加，后续依据使用数据决定 |

## 2. 页面结构

- 微信原生导航：标题“全部工具”，保留系统返回和右上角胶囊，不重复绘制返回按钮。
- 顶部固定搜索框：占位“搜索工具名称或用途”，右侧在有输入时显示清除图标。
- 搜索框下方固定一行分类 Tab：全部、图像、文本、文档、查询、计算。“全部”为聚合入口，不计入五个业务分类。蓝色文字加短下划线标识选中态，无胶囊底色、不显示数量徽标。
- 下方全宽目录：按类别分组，组标题显示该组工具数量；每行两个入口，包含自绘 SVG 图标、名称和一行用途描述。
- 默认选中“全部”，按图像、文本、文档、查询、计算顺序分组，每个工具只出现一次。没有新的 Hero、广告占位或重复的隐私说明。
- 二级目录页不增加底部菜单；首页、记录、我的原有一级页面和底部菜单保持不变。

## 4. 交互规则

### 浏览与返回

- 点击顶部 Tab，目录只展示该类工具并回到列表顶部。六个 Tab 等分可用宽度；标签超出屏宽时横向滑动，不挤小字体、不折成两行，选中项自动进入可见区域。
- 查询、计算暂无已上线工具时，显示“该分类暂无工具”，辅助文案“先看看其他实用工具吧”，提供“查看全部工具”按钮；不承诺上线时间，不放虚构工具。
- 默认“全部”按组连续浏览；滚动时不自动改变分类选中态，避免分类筛选与滚动定位混淆。
- 点击工具进入已有工具页面，沿用现有最近使用逻辑。仅打开目录不新增最近使用或操作记录。
- 从工具返回目录，恢复原来的分类、搜索词与列表滚动位置；从目录返回首页使用微信原生返回。
- 分享好友与朋友圈沿用全站统一分享图，分享打开默认目录，不附带用户搜索词。

### 搜索

- 输入后在本地匹配工具名称、用途和有限的同义关键词，不联网、不保存搜索记录。
- 匹配忽略大小写及首尾空格。例如“证件照”能找到尺寸修改，“九宫格”能找到图片拆块，“PDF”能找到图片转 PDF。
- 输入搜索词后进入全目录搜索，暂时隐藏顶部分类 Tab，结果区域继续使用全宽双列布局，避免选中的分类造成漏查误解。
- 搜索标题显示“搜索结果”和实际匹配数量。清除搜索词后恢复搜索前的分类与滚动位置。
- 无结果文案：“没有找到相关工具”，辅助文案：“试试更简短的工具名称或用途”；提供“清空搜索”操作。
- 搜索在输入法组合输入结束后更新；筛选时不主动关闭键盘，点击结果或空白处可收起键盘。

## 5. 视觉规范

- 延续现有白色 / 浅灰页面、蓝色选中态和多色自绘 SVG，不重做整个小程序的视觉系统。
- 以 375 px 宽度设计：无侧栏，目录左右内边距 16 px，双列间距 10 px，工具项高度至少 112 px。
- 顶部 Tab 高度 46 px、字号 14 px，选中下划线宽 24 px、高 3 px；工具数量只显示在目录分组标题右侧。
- 工具图标容器 36 × 36 px；名称 14 px / 20 px；描述由第一版的 10 px 增大到 11 px / 17 px；正文不采用随屏宽缩放的字号。
- 工具项圆角 8 px，细边框，不嵌套卡片；分组标题使用开放布局。
- 分类触控高度 46 px，搜索框高度 44 px；选中状态不只依赖颜色。
- 320 px 窄屏不截断名称与描述，必要时描述换行、工具项随内容增高，不横向溢出。
- 底部适配安全区；搜索与分类保持可达，列表自行滚动；减少动效，无扫光或大幅入场动画。

## 6. 后续扩展原则

### 已确定分类

顶部展示：**全部 / 图像 / 文本 / 文档 / 查询 / 计算**。“全部”是聚合入口，不是业务分类。

采用用户确定的五个业务大类，后续新增工具优先在这五类中归属：

| 顶部 Tab | 包含的用途 | 示例与边界 |
| --- | --- | --- |
| 图像 | 图片处理与输出 | 压缩、尺寸、拆块、拼接、水印 |
| 文本 | 文字整理与分析 | 字数、清洗、比对、字体；未来可加繁简转换 |
| 文档 | PDF 与办公文件处理 | 当前图片转 PDF；未来可扩展 PDF 合并、拆分、文件转换 |
| 查询 | 根据关键词或标识查找已有信息 | 未来的邮编、区号、节假日查询等；是否需要在线接口逐个工具明确 |
| 计算 | 根据输入计算或换算结果 | 未来的单位换算、日期间隔、比例折扣等；数值推导归计算，不归查询 |

不建议此时拆出“压缩 / 转换 / 编辑”：这些动作横跨图片和文档，容易让用户判断困难。也不建议设置“热门 / 推荐 / 常用”为业务分类，首页已承担精选和最近使用。

不先增加“AI / 开发 / 音视频”分类。AI 是实现方式，抠图等工具仍应按用途归类；开发、音视频要等实际产品方向和工具数量明确后再决定是否独立。

本次检索参考（2026-09-08 实际查看页面）：

- [ToolKit 工具箱](https://toolkit.teckbest.com/)：按图片、文本、计算 / 转换、实用、开发者、文档、音视频等分组。借鉴对象明确的大类，不照搬其较多的分类数量。
- [iLoveIMG](https://www.iloveimg.com/zh-cn)：图片领域内部使用全部、优化、创建、编辑、转换、安全。适合单一图片产品内部细分，不适合作为本小程序跨图片、文字、文档的一层总分类。

五类名称与顺序以用户本次确认为准；上述检索仅作为分类边界的参考。未来示例不表示功能已经上线。

### 目录维护

- 统一维护工具目录：唯一标识、名称、用途、分类、图标、颜色、页面地址、搜索关键词、排序与可用状态。
- 首页精选和全部工具使用同一份工具元数据，避免图标、名称或链接不同步；不为本次需求重构其他工具内部功能。
- 固定保留用户确定的五个分类 Tab，空分类使用统一空状态；“全部”不展示空分组。后续工具无法自然归入这五类时，再讨论分类调整，不擅自增加“生活”等新分类。
- 同一工具只属于一个主要分类；其他用途通过搜索关键词覆盖，避免“全部”出现重复入口。
- 先使用本地目录和本地搜索，不增加服务器、账号、排行榜、收藏、推荐算法或搜索历史。
- 工具数量明显增多后再按真机性能决定是否分包、分批渲染，不因远期可能性提前增加复杂度。

## 7. 设计稿与验收边界

`设计稿.html` 是独立评审稿，不是小程序生产页面。三屏分别展示全部目录、文本 Tab 选中、用途搜索；每屏均可以切换五类、搜索与清空，点击查询或计算可查看分类空状态，输入“音频剪辑”可查看搜索无结果状态。

确认设计后才修改首页入口、注册小程序页面并接入真实工具路由。本次不修改生产代码、不重启微信开发者工具、不生成开发包。

实施后需要验证：10 个工具路由全部正确；原生返回不闪屏；搜索与分类切换正确；返回时状态保留；空结果可恢复；320 / 375 / 430 px 不溢出；微信键盘与安全区不遮挡内容；好友和朋友圈分享可用。
