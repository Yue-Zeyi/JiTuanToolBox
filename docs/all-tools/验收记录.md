# 全部工具 · 实现与验收

日期：2026-09-08。

## 实现范围

已将第三版设计接入 `pages/all-tools/all-tools`，首页“全部工具”进入真实目录，不再显示开发中提示。

- 分类：全部、图像、文本、文档、查询、计算。
- 图像 5 个、文本 4 个、文档 1 个；查询和计算使用空状态，“全部”跳过空分组。
- 本地名称 / 用途 / 关键词搜索，搜索期间隐藏 Tab，清空恢复分类和滚动位置。
- 现有 10 个工具可跳转，返回保留目录状态，导航成功记录最近使用，不新增操作记录。
- 原生返回与导航，现有好友和朋友圈分享图，不携带搜索词。
- 首页精选顺序与描述不变，工具信息由 `utils/tool-catalog.js` 统一提供。

## 自动验证

`node --test --test-reporter=spec tests/*.test.js`：64 项通过，其中新增目录专项 11 项。三个新增或修改的业务 JS 文件通过 `node --check`。

独立只读代码审查发现快速切换分类并输入、清空后立即再次输入时的异步状态竞争。已先用延迟 `setData` 回调复现两种错误，再修复逻辑状态的同步更新；两项回归测试覆盖分类和滚动位置恢复。

在现有微信开发者工具中，通过官方 miniprogram-automator 实际完成：

1. 从首页点击全部工具进入目录。
2. 六个 Tab 切换，验证各类工具数量、查询和计算空状态。
3. 用“证件照”和带首尾空格的“pDf”跨分类搜索。
4. 将目录滚动到 180 px，搜索后清空，恢复同一实际滚动位置。
5. 逐个点击全部 10 个工具，确认实际路由，再返回目录确认搜索状态不变。
6. 搜索无结果后清空恢复原分类；分类为空时返回全部工具。
7. 检查目录区域、Tab 和卡片边界；工具按钮双列同顶对齐，无横向越界。
8. 读取并确认操作记录未改变；验收结束恢复最近使用数据。未模拟或绕过内容安全服务。

自动化连接第一次超时，通过官方 CLI 重新启用当前项目自动化后恢复；未关闭或重启微信开发者工具，未生成开发包。

## 视觉复核

实际设备配置：iPhone 12/13 (Pro) 模拟器，逻辑宽度 390 px。截图经人工图像查看复核，包括默认目录、文本、文档、查询空状态、用途搜索、搜索无结果。

| 检查项 | 结果 |
| --- | --- |
| 标题与分类 | 原生“全部工具”标题，六个顶部 Tab 顺序一致，无重复返回 |
| 页面结构 | 固定搜索与分类，下面独立滚动的双列工具目录，无侧栏或新底部 Tab |
